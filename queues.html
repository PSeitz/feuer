Lookup and shared work

Memory hits perform no disk I/O. A disk lookup first tries its shard's small-entry buffer. Otherwise it finds the object's payload address, length, and checksum in the in-memory index. Absent entries fall through to the source callback.

Matching concurrent public misses share one disk-or-callback operation by object key and callback error type. Storage also shares reads for the same indexed entry. Cancellation can leave the result unset so a waiter takes over.

Payload admission before allocation

A persisted-object read acquires one of 64 payload permits before allocating its object buffer. The file layer reserves channel capacity before preparing each I/O request. Large reads submit pieces of at most 1 MiB, with fresh reservations for subsequent pieces.

Recovery also reserves low-level queue capacity before allocating metadata-read buffers. Queue slot counts do not limit the combined capacity of all live object buffers.

Optional source fallthrough under disk pressure

When at least 64 payload reads are waiting, Feuer schedules each unchecked waiter's decision closure. A true result invokes the usual source callback instead of waiting for a permit. Each decision runs at most once in its caller's task, even if earlier decisions have reduced pressure.

Memory hits, buffered hits, absent entries, admitted reads, and shared-read waiters skip the decision. Shared public fetches follow their executing caller's decision. A takeover after cancellation uses its own closure.

Fallthrough does not cancel submitted I/O or remove the disk entry. Source errors return without retrying disk. APIs without a fallthrough closure always wait.

Whole-object verification and promotion

Reads verify the complete payload against its expected checksum. They do not read neighboring entries or metadata on the lookup path. I/O errors become misses without removing the entry. Checksum failures invalidate only the entry still associated with that read.

Readers retain no disk reservation. Eviction can release chunks while I/O is outstanding, so reuse can cause a checksum miss. Successful results promote the complete object to memory and charge retained allocation capacity. Disk hits do not schedule another write.

Best-effort queue admission

Newly admitted downloads are queued unless the object is already stored. A full or closed queue skips the write without failing the lookup. Queued and active writes proceed independently of memory retention.

The queue limits object count, not payload bytes. Pending-byte metrics cover logical payloads through preparation and completion, excluding padding. Memory eviction does not cancel admitted writes.

Small-entry buffering and chunk reservation

Objects below 512 KiB aligned size are copied into a per-shard 1-MiB buffer, releasing incoming buffers. Full/no-fit chunks flush immediately, partial chunks every 60 seconds. Larger objects write separately. Closing discards partial chunks.

Buffering reserves no disk capacity. Flushing reserves payload chunks, evicting sampled objects if needed. A multi-chunk payload requires consecutive whole chunks. Fragmentation or exhausted eviction budgets can skip admission.

Lookups can copy complete buffered objects after memory eviction. Busy/flushing buffers can miss until publication.

Payload completion, publication, and metadata

Payload I/O must succeed before publication. Publication rechecks the object key and requires metadata capacity for the flush. Redundant objects or writes without sufficient metadata capacity are discarded.

Metadata occupies separate chunks. A periodic writer persists dirty 4-KiB pages every second. New metadata chunks are written before links to them. No cache API promises a flush or crash durability.

Small objects may share a payload chunk. Removing one does not necessarily release a chunk. A chunk can be reused after its last entry is removed, without waiting for readers or old metadata to be rewritten.

Format, ordering, and recovery

Sharing I/O queues

Pass clones of IoQueues::new()? to independent caches to share admission, rings, and worker threads. None creates dedicated queues. Read and write workers remain separate and can make progress concurrently.

Scheduling follows arrival order without per-cache fairness. Each cache keeps its own contents, capacities, buffer pool, history, lock file, and background-write queue. Dropping one cache does not stop others. Submitted I/O retains buffers, files, and locks through completion.

Zero disk capacity creates no I/O queues. Disk-enabled caches require Linux direct I/O and io_uring.

Trace delivery

Trace starts and outcomes enter a 65,536-event channel. A full channel waits rather than dropping events. One worker delivers binary packages when its batch reaches 8 MiB or all handles are dropped. There is no timed delivery. Slow receivers delay lookups.

Receiver errors stop delivery without changing cache results. Dropping handles does not wait for persistence. See the whole-object trace format and receiver contract.
